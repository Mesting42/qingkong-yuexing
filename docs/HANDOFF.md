# 开发交接

```text

  types.ts               逻辑单位、状态、角色、障碍、星星、存档的数据结构
```

## 系统关系

输入调用 Game 动作；Game 每个固定步更新物理、障碍、碰撞、计分和道具，再通过事件通知 UI/音频。Renderer 只读取当前世界，不改变规则。Storage 负责完整局的单次结算。任务从存档与未结算局计算进度，领取时检查已领取 ID。

主要顺序是：输入 → 固定步 → 物理/障碍移动 → 事故处理 → 穿越计分 → 拾星 → 回收离场对象。碰撞优先于奖励，避免死亡后仍在同一步收集整排星星。

## 坐标、物理与插值

- 所有规则使用逻辑像素和秒。世界 432×768，地面 y=748，角色横坐标 112。
- 重力 840 px/s²，拍翼速度 -302 px/s，最大下落速度 500 px/s。每次拍翼重设 vy。
- 主循环固定 120Hz；显示帧插值位置，刷新率不参与规则。
- 单帧卡顿超过 300ms 会自动暂停，后台时间不被补算。
- 碰撞体只覆盖主体，半宽 14、半高 11。翅膀、尾羽和配饰不扩大碰撞。
- 障碍按相对运动变换后进行线段与扩张矩形检测；移动间隙的前后中心也参与计算。
- 通过计分平面时插值鸟的位置和间隙中心。每组 `scored` 只写一次。

## 路线与难度

`difficulty()` 定义七个阶段，达到上限后保持稳定，不无限加速。每组门生成时冻结速度、宽度、间隙和移动幅度；不改变已可见的规则。

`Generator` 从上一组中心生成有限高度差。混乱模式在这个相关序列上叠加波浪关系和缓慢正弦移动，移动幅度从安全空间中预先扣除。`canTraverse()` 按 30Hz 对“拍翼/不拍翼”两种动作做格点去重与束搜索，并要求离开上一组、进入下一组时留出主体空间。搜索失败时退回前一中心。

搜索是保守的数值筛查，不是对所有操作误差的数学证明。实际游玩仍需调校。当前测试包含两模式七阶段的 630 组候选和各 12 分钟物理驾驶模拟。

调整难度时，先改 `config.ts`，再运行 `npm test`，最后实际操作。不要直接更改重力来制作混乱模式，也不要改屏幕缩放来改变预警时间。

## 护盾与磁铁边界

实际拾星维护 `picked`，收益维护 `stars`，局外余额维护 `balance`；三者不可混用。

星星不能产生护盾。ShieldDrops 按生成的障碍组数随机排期，每隔20～30组才在安全间隙中心生成一个独立拾取物；持有时冻结排期且不生成，消耗时重置完整间隔。护盾随所属移动间隙同步，磁铁不影响它。collectShield 只有一个 boolean 容量，已持有时直接拒绝，不记录备用次数，也不延长恢复时间。重复拾取的对象仍正常回收。事故发生时，立即移除当前护盾、归零连击，将角色移到门的安全中心或合理边界位置，设温和的上升速度。2.2 秒恢复区间内可能接触的门整组标记 `harmless` 并淡化，防止保护结束时卡在原障碍中。它们可以获得基础分，不能精准奖励。

磁铁每局一次。星星向鸟的位置插值吸附，障碍和物理不受影响。磁铁时间只在 `flying` 推进；重试用新 Run 清空所有旧状态。

## 状态与奖励防重

```text
主页 → 准备 → 飞行 → 失败反馈 → 结算 → 准备/主页
                ↓
               暂停 → 恢复倒数 → 飞行
```

准备时暂停，继续后仍回到准备状态，不会偷偷开始下落。暂停会清理按下状态与已调度短音源；恢复不会补发按键。

失败或结束本局时，`Storage.settle` 检查 `run.settled` 及最近 32 个已结算 Run ID，然后在同一个保存动作中更新收益、纪录和累计任务。任务另以 `claimed` ID 数组防重。外观已解锁后只装备，不再扣款。

## 扩展主题、外观、任务

**主题**：在 `ThemeId` 和 `THEMES` 增加主题，在 `public/art/` 添加对应图片；补充 `art.ts` 的环境与障碍分支。不能只换背景色。不要让装饰进入安全间隙。

**外观**：在 `SKINS` 增加 ID、中文名称、价格、条件和配色；需要新轮廓时扩展 `feature` 联合类型及 `drawBird()` 分支。预览和游戏共用绘制函数，碰撞和飞行参数保持不变。

**任务**：在 `MISSIONS` 增加唯一 ID、描述、目标、奖励和纯进度函数。需要新累计值时先扩展 Stats，并在存档解码及单次结算中接通。发布后不要把旧 ID 复用为新奖励。

**存档版本**：当前 v1 为首发格式，没有历史迁移。未来升级应添加明确的 v1→v2 转换，保留已有购买与已领取记录；当前解码器对未知未来版本安全回退，不能把该回退当作迁移方案。

## 性能与调试

DPR 上限 1.75；粒子最多 90 个；离场门、星星和到期粒子及时回收；短音复音上限 24，共用总线。耐久测试中的门/星峰值为 3/7，粒子未超过上限。

开发预览会在游戏 canvas 的 `data-telemetry` 和 `window.clearwingSnapshot()` 中提供只读副本，供真实输入回放观察。它们不能改分或强制结算；生产构建会移除这两个开发入口。

本次不接入后端、云同步、服务工作线程或付费服务。已知兼容性边界见 README 和 TESTING.md。
